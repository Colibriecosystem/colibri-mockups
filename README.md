# Colibri — макеты интерфейса

Статические HTML-макеты того, что мы обсуждаем до того, как это построено. Публикуются на GitHub
Pages, чтобы ссылку можно было просто открыть и оставить замечания.

**Живая версия: https://colibriecosystem.github.io/colibri-mockups/**

Замечания — в [issues](https://github.com/Colibriecosystem/colibri-mockups/issues) этого
репозитория. Пишите про вариант и строку: «во втором варианте описание длинное, но виджетов на экран
влезает четыре» полезнее, чем «второй лучше».

## Как смотреть

Откройте ссылку. Всё работает без сервера и без сборки — можно и склонировать репозиторий и открыть
`index.html` двойным кликом. Нужен Chromium 111+ (`color-mix()` и container queries), то есть
свежие Chrome, Edge или Opera.

На каждой странице макета работают:

- переключатель темы (тёмная / светлая / как в системе) и языка (`RU｜EN`) в шапке — выбор
  запоминается;
- нижняя жёлтая полоса **MOCKUP** — она не часть интерфейса, а пульт: ширина окна 1024 / 1280,
  10 или 28 виджетов (чтобы посмотреть пагинацию), сортировка, зарезервированное место под ♥,
  «развернуть всё» в третьем варианте.

Параметры в адресе делают то же самое для одной загрузки: `?vw=1024`, `?lang=en`, `?rows=28`,
`?sort=installs`, `?likes=1`, `?expand=all`. И `?bare=1` — спрятать нижнюю полосу, если нужен
скриншот.

## Что настоящее, а что нарисовано

Данные виджетов настоящие: имена, версии, авторы, категории, теги, описания на двух языках, режим,
хеш, размер, права и список доменов — всё из публичного каталога.

**Всё, что подчёркнуто пунктиром, — заглушка**: количество установок, активные за 7 дней, даты и
бейдж NEW. Этих полей ещё нет, они появятся отдельной работой. Поэтому одна строка в каталоге
намеренно оставлена совсем без счётчиков и дат — так видно правило: нет данных, значит не показываем
ничего. Не ноль и не «добавлен сегодня». Сортировка по установкам или по датам ставит такую строку
в конец.

Место под ♥ — отдельная итерация рейтинга. Оно помечено пунктиром и по умолчанию скрыто; включается
кнопкой на нижней полосе. Никакой вариант вокруг него не построен.

## Как это устроено

Каждая страница макета — это только «рама» (заголовок окна, вкладки, рейка категорий, поиск,
сортировка) плюс пустой контейнер. Все десять строк рисует один общий модуль, поэтому порядок чипов
или состояние кнопки физически не могут разойтись между вариантами. Правила кнопки живут в одной
функции: основная кнопка всегда видна и меняется по состоянию, обновление важнее «открыть», а у
установленного виджета, который умеет только панель, кнопки нет вовсе — только галочка и пометка.

Цвет называет семейство действия: оранжевый — «скачать байты» (установить, обновить), зелёный —
«уже есть» (открыть в окне). Зелёный элемент в строке ровно один.

Оформление — токены и компоненты дизайн-системы Nest; в макетах переопределены только два акцентных
цвета, потому что это макет ДЕСКТОПНОГО окна, а не сайта.

Шрифт IBM Plex подгружается из Google Fonts. Без интернета страница откатится на системный шрифт —
вёрстка не поедет, метрики чуть другие.

## Файлы

```
index.html                 эта витрина
nest-catalog/
  index.html               оглавление варианта + чек-лист ревью
  variant-1-dense.html     плотная таблица
  variant-2-cards.html     карточки-строки
  variant-3-expand.html    двухуровневая строка
  catalog-data.js          десять виджетов, состояния строк и три рендерера
  catalog-i18n.js          все строки, оба языка
  catalog.css              всё оформление макета
  kit/                     токены и компоненты дизайн-системы Nest
```

`kit/` не редактируется: обновление дизайн-системы — это замена файлов целиком, а не правки поверх.
Всё, что нужно макету сверх неё, лежит в `catalog.css`, `catalog-i18n.js` и `catalog-data.js`.
